## API Key Pool Management (2026-10-20)

- Added a separate `/cards/manage` page linked from `/cards`, with add/label, masked-key hint, active-session count, enable/disable, refresh, and removal controls. Disabling excludes the key from new sessions without interrupting existing sessions. The home try-on page remains unchanged; existing provider-key selection and session request/response shapes remain compatible.
- Added local admin API routes under `/api/admin/provider-keys`. They require an allowed loopback Origin and a loopback peer address; Docker trusts Nginx's overwritten `X-Real-IP` only when `ANYWEAR_TRUST_PROXY=true`. The management view never returns credential values, and deletion is rejected while a key has active sessions.
- Added stable `provider-key-N` IDs and rotating pool revisions for changes. The current `.env` keys seed the pool until the first management change; subsequent changes persist atomically to `provider-keys.json` under `ANYWEAR_DATA_DIR` or `.anywear-data`. The file is ignored by Git and contains plaintext credentials. Docker stores it in the persistent `anywear-data` volume; `docker compose down -v` removes that data.

Desktop and 390px layout were visually checked with no horizontal overflow. Docker services were rebuilt and are running; local browser access to `/cards/manage` loads all seven cards, and the LAN Nginx route returns 403. No Decart request was made.
- Docker admin requests are authorized only for loopback Origins and either loopback peers, the detected Docker host gateway (for the host-loopback-only published backend port), or the resolved `frontend` service IP with a loopback/Docker-gateway forwarded address. Other containers cannot authorize themselves with a forged forwarding header, and LAN client addresses are rejected. The backend port is published on host loopback only so the existing local Vite server can proxy API/WebSocket traffic without exposing the backend to LAN clients.
- The browser omits `Origin` on same-origin GET in this runtime; management reads fall back to the allowed loopback `Referer`. No add/remove/toggle was performed in the live pool.
- The file-backed store serializes management operations within one server process. Do not run multiple backend instances against one `ANYWEAR_DATA_DIR`; this demo deployment uses one backend instance.
- Remaining checks: rebuild the Docker stack and verify local browser access to `/cards/manage`; confirm management remains blocked on the LAN URL. No camera or paid generation request is required.

## LAN Camera Diagnosis and Logs

- The `getUserMedia` undefined error occurs because browsers disable camera APIs on an HTTP LAN IP; localhost is exempt, but `http://192.168.x.x` is not a secure context.
- The client now checks secure-context and camera API support before requesting a billable session, then acquires the camera before creating a session. It shows an HTTPS-specific message instead of a TypeError.
- Browser diagnostics persist up to 300 sanitized entries in local storage and can be exported from the control panel. They record origin/security state, camera settings, signaling and WebRTC transitions, and errors; they exclude video, garment bytes, signaling payloads, and API credentials.
- Fastify logs origin rejections and session/provider socket lifecycle events. Nginx writes structured access/error logs to container output without query strings. Docker rotates each service's logs at 10 MB, retaining three files.
- Verification: `npm run typecheck`, `npm run build`, `npm run test -w server` (10 tests), and `docker compose config --quiet` passed. The deployed LAN page returns HTTP 200 and displays the insecure-context warning; an unlisted-origin session request returns 403 and emits the structured `origin.rejected` backend event without creating a session.
- Added a LAN HTTPS listener on host port `5443` while retaining HTTP `5173`. Nginx serves `/lan-ca.crt`; Compose mounts the host-generated certificate read-only, and `.certs` is excluded from Git and Docker build context. `scripts/setup-lan-https.ps1` creates the IP-SAN certificate without installing a system trust root.
- HTTPS smoke checks: the server certificate chain validates against the generated CA; HTTPS page returns 200 (transport smoke used certificate-validation bypass), CA download returns 200, and HTTPS Origin preflight returns 204 with the expected allow-origin. The live browser has not imported the generated CA, and camera permission/generation were not tested.
- Remaining client setup: compare SHA-256 `2053CB3FCD7BD1E63A84116B7092AFB3626A98B01D3251E854EB7F19344CD754`, import the downloaded `lan-ca.crt` into the remote Windows user's Trusted Root Certification Authorities, then browse to `https://192.168.1.9:5443`. ## Changes

- Replaced the five active SVG reference-image URLs with 1024×759 PNGs. Decart VTON supports JPEG, PNG, and WebP reference images.
- Combined each image and its garment-specific prompt into one `set_image` message.
- Enabled garment selection before starting and during an active session. During a pending change, further clicks keep the latest choice queued and visibly marked; changes are sent serially.
- Start the 30-second garment acknowledgment timer only after `set_image` is actually sent. Treat an ACK without a `success` field as accepted unless it explicitly reports `success: false`.
- Treat provider errors as session-fatal and clear pending selections, preventing late acknowledgments from being attributed to the next garment when the protocol provides no request ID.
- Guard asynchronous teardown completion with a lifecycle token so an older stop/error cleanup cannot overwrite a newer user action or session state.
- Fixed session start/stop requests: Fastify rejects a request with `Content-Type: application/json` and no body with 400, while the global handler previously returned 500. The client now sends an empty JSON object (no request fields added), and the handler preserves 4xx status codes.
- Restricted CORS and session-changing HTTP/WebSocket requests to configured local app origins, preventing arbitrary websites from creating billable sessions through the local service.
- Classified Vite and its React plugin as client development dependencies; Docker's backend stage now installs only production dependencies for the server workspace instead of copying the full build toolchain.
- Reject `set_image` messages with `null` image data; the demo always sends a base64 garment image, and null could otherwise be forwarded upstream as an invalid reference.
- Kept rejected prompt/image feedback visible and fixed startup and React StrictMode cleanup behavior.
- Bounded browser and server signaling queues, and close a partially-created WebRTC connection if session startup fails.
- Moved source SVGs out of the publicly served client assets and into `assets/garments/source-svg`.
- Limited the server's queued signaling payload by both message count and total bytes, validate required/base64 reference-image data and decoded size, and return the session to `connected` after an image acknowledgment.
- Standardized Node.js on supported 22/24 lines, defaulting to the locally verified `24.18.1` in `.nvmrc`; pinned both Docker Node stages to the same patch version and declared npm `11.16.0` in the root manifest.
- Added in-page garment upload for JPG, PNG, and WebP files up to 10 MiB; uploaded images remain in page memory only and can be selected before or during a session.
- Added the `extension` Chrome MV3 package: clicking an image on an HTTP/HTTPS page opens a 460×820 Anywear popup and passes the image into the compact page. The popup reports a clear startup error when the local app is unavailable.
- Added compact-mode single-column layout rules so the popup remains usable even when its viewport is wider than the intended window size.
- Added a backend Decart API Key pool: `DECART_API_KEYS` accepts comma/newline-separated keys and combines with the legacy `DECART_API_KEY`, deduplicating entries. Sessions use least-active round-robin assignment.
- Set the key-pool cooldown default to zero so a failed key remains eligible and the pool cannot be exhausted by cooldowns. Provider errors still stop the affected live session; a new session can retry through the pool. Added config, pool, and local mock-WebSocket retry coverage.
- Added read-only folder-backed garment groups configured through `GARMENT_GROUPS_JSON` and `GARMENT_LIBRARY_HOST_PATH`; group listing returns all JPG/JPEG/PNG/WebP previews, image reads are restricted to the configured root, and Docker mounts the host library read-only.
- Added a visible `选择图组目录` control beside the garment panel actions. Browser directory selection imports supported images as a temporary local group without sending absolute paths or changing backend APIs; imported groups survive the initial garment-list fetch but are not persisted across page refreshes.
- Rebranded the app and Chrome extension as 青叶科技. The cropped supplied logo is used in the app and browser icon sets; the UI uses a graphite palette with silver brand controls and restrained cool-cyan interaction accents. Browser title/favicon, extension labels, and README titles are updated; internal `anywear-*` identifiers remain unchanged.
- Added an API key pool detail page at `/cards`; the home page exposes only a key icon entry, while card status and selection remain off the main try-on screen. A manually selected card persists for future new sessions until changed; automatic least-active rotation remains the default.
